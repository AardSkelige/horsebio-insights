# Бэкап боевого сервера

## Как устроено

`horsebio-backup.sh` крутится по crontab в 3:30 и складывает два архива:
`full` (всё, включая зеркало МойСклада и логи прогонов, ~10 МБ) и `valuable`
(только то, что синхронизацией не восстановится, ~4 МБ). Внутри архива —
дамп базы (`db/full.dump`, формат custom), тома Caddy с ACME-аккаунтом,
`.env.prod` обоих проектов, `docker-compose.prod.yml`, `Caddyfile` и crontab.
Опись каждого архива лежит рядом с содержимым, в `MANIFEST.txt`.

Полки и сроки: `daily` 14, `weekly` 8, `monthly` 12, `valuable` 90. В weekly
и monthly кладётся **копия**, а не перенос — суточная полка должна оставаться
сплошной. Ротация идёт только после успешной упаковки: старое не удаляется,
пока новое не создано.

Состояние прогона пишется в `/root/backup/state/status.json` — и при успехе,
и при провале. Его читает проверка «Бэкапы» на странице `/checks`; в контейнер
приложения монтируется только этот каталог, потому что в самих архивах лежат
`.env.prod` и приватные ключи.

## Где что живёт

| | |
|---|---|
| Источник истины | этот каталог в репозитории |
| На сервере | `/root/horsebio/deploy/backup/horsebio-backup.sh` (кладёт деплой) |
| Архивы и состояние | `/root/backup/` — вне репозитория, разумеется |
| Лог | `/var/log/horsebio-backup.log` |

До 09.09.2026 скрипт жил только в `/root/backup/backup.sh`, и его правки
не были видны ни в истории, ни в ревью. Правим здесь, выкатываем деплоем.

## Установка

> Строку в crontab деплой не ставит — он только копирует файлы. Это ручной шаг.

```bash
crontab -l | grep -c horsebio-backup     # → 1
```

```
30 3 * * * /root/horsebio/deploy/backup/horsebio-backup.sh >/dev/null 2>&1
```

## Грабли: удалённый том воскресает

Скрипт архивирует тома через `docker run --rm -v <том>:/src`, а такая команда
**создаёт** том, если его нет. 07.09.2026 семь томов с состоянием роботов
удалили после переезда в Postgres, а список в скрипте не поправили — и с 08.09
каждую ночь появлялись семь пустых томов, а в архив ложились семь пустых
`.tar.gz` по 86 байт, выглядевших как бэкап состояния.

Правило простое: **удаляя том, проверить, не перечислен ли он в этом скрипте.**
Сейчас в списке только тома Caddy — там ACME-аккаунт, потеря которого упирается
в лимит Let's Encrypt на повторные выпуски.

## Проверки

```bash
/root/horsebio/deploy/backup/horsebio-backup.sh --dry-run   # ничего не пишет
tar -tzf /root/backup/daily/horsebio-full-$(date +%F).tar.gz  # состав архива
```

В составе обязаны быть `db/full.dump`, `config/`, `caddy/`, `MANIFEST.txt`.
Пустые архивы по 86 байт означают том, которого больше нет, — см. выше.
