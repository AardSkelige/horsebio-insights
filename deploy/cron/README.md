# Проверки по расписанию

## Как устроено

Cron вызывает `horsebio-check.sh`, тот запускает `manage.py run_check <id>`
внутри контейнера бэкенда. Команда порождает скрипт, дожидается его, пишет
лог и код выхода — то же самое, что делает кнопка «Запустить» на странице
«Проверки». Место запуска одно, и ночной прогон ничем не отличается
от ручного.

Раньше cron ходил в приложение по HTTP: `curl` на `http://localhost:8001`
с `CRON_SECRET` в crontab открытым текстом. Ради этого приходилось держать
опубликованным порт, на котором висит админка Django. Ни порт, ни секрет
больше не нужны.

Защита от наложения двойная: `flock` не даёт запуститься второму процессу,
pid-файл в `scripts_logs` — второму прогону внутри контейнера. Первая
экономит память, второй защищает данные; ни одна не заменяет другую.
Обе отдают код 75 — «пропуск», а не «ошибка».

Предел времени у каждой задачи свой и живёт в реестре
(`backend/api/services/scripts_registry.py`), а не в crontab: там же лежит
всё остальное знание о задаче. Прогон сверх предела снимается с кодом 124,
и это видно в карточке проверки.

## Установка

> **Строки в crontab деплой не ставит — он только копирует файлы.** Это ручной
> шаг, и в соседнем проекте его один раз уже пропустили: расписание пролежало
> в репозитории нетронутым, а синхронизация три дня шла только по кнопке.
> Второй раз, 05.09.2026, демон приехал деплоем, а строку в crontab добавили
> руками через несколько дней.
>
> Проверять командой, а не наличием файла:
> `crontab -l | grep -c '^[^#].*horsebio-check'` — должно быть 21, а не 0.
> И `crontab -l | grep -c 'api/scripts'` — должно быть 0: одного счётчика мало,
> он не видит оставшиеся старые строки.

Строки этого файла **заменяют** прежние с `curl`, а не добавляются к ним:
иначе каждую проверку запускали бы двое, и расписания разошлись бы молча.

```bash
# Файлы едут сами при деплое бэкенда. Вручную:
scp -r deploy root@<сервер>:/root/horsebio/
ssh root@<сервер> 'chmod +x /root/horsebio/deploy/cron/horsebio-check.sh'

# Бэкап перед любой правкой
ssh root@<сервер> 'crontab -l > /root/crontab.bak.$(date +%Y%m%d_%H%M%S)'

# Замена по одной проверке — так переносили 05.09.2026:
crontab -l | sed 's|curl .*api/scripts/<id>/run/.*|/root/horsebio/deploy/cron/horsebio-check.sh <id>|' | crontab -

# Когда перенесены все — убрать шапку с секретом
crontab -l | grep -v '^CRON_SECRET=' | grep -v '^API=' | crontab -
```

Проверка после переноса — обе строки обязательны:

```bash
crontab -l | grep -c '^[^#].*horsebio-check'   # 21 — новые строки на месте
crontab -l | grep -c 'api/scripts'             # 0  — старых не осталось
```

## Ручной прогон

```bash
docker compose -f /root/horsebio/docker-compose.prod.yml exec -T backend \
    python manage.py run_check --list          # какие вообще есть
/root/horsebio/deploy/cron/horsebio-check.sh horsebio_backup   # как ночью
```

Коды выхода: код самого скрипта, `75` — прогон уже идёт (пропуск),
`124` — снят по сроку, `2` — нет такой проверки.

## Журнал

`/var/log/horsebio_cron.log`, по строке на прогон с отметкой времени. Ротация
уже настроена (`/etc/logrotate.d/horsebio`). Подробный вывод каждого прогона —
не здесь, а в карточке проверки и в `scripts_logs` внутри контейнера.
